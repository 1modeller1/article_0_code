### Код к статье "Применимость описания взаимодействий экономических факторов функциями распределения"

### Функция
Данный скрипт предназначен для работы с данными `ofdata.ru`. Он:
- Убирает выбросы (если у более, чем 1% компаний одно и то же значение показателя)
- Убирает ошибки вида +- (Для различных видов затрат одни компании пишут показатель как +, другие как -. Из-за этого могут возникать ошибки, поэтому все показатели приводятся в должный вид)
- При необходимости можно разделить данные строки отчетности на положительные и отрицательные величины для их отдельного анализа, поскольку как правило их распределения ведут себя независимо (например получится `c2300p` и `c2300m`).
- Можно посчитать по МНК коэффициенты a и b для каждой строки относительно любого показателя из отчетности для уменьшения мультиколлинеарности между ними
- Можно получить csv файл с парными коэффициентами корреляции между каждой строкой отчетности

### Требования для работы со скриптом:
- Установить PostgreSQL
- Скачать базу данных финансовой отчетности с ofdata.ru (Можно бесплатную)

Таблица на сайте имеет формат:
```json
{
  "inn": "7707049388",
  "data" : {
    "2020" : {
      "1100" : "444939649000",
      "1110" : "60106000",
      ... 
    },
    "2019" : {
      "1100" : "496998524000",
      "1110" : "96831000",
      ...
    }
  },
  "object_data": { ... }
}
```
Ее нужно привести к формату
```json
{
  "inn" : "444939649000",
  "year" : "2020",
  "data" : {
      "1100" : "444939649000",
      "1110" : "60106000",
      ... 
  }
}
```
Я это делал уже очень давно и поэтому дать нужный скрипт не смогу. У меня там вообще 2 таблицы в круг почему-то замыкаются, меняя друг друга. Желания скачивать сырую БД и заново преобразовывать ее тоже нет, поэтому вот ИИшный совет как привести ее к нужному формату.
```postgresql
CREATE TABLE fin_data AS
SELECT
    t.inn,
    kv.key::int AS year,
    kv.value    AS data
FROM raw_data,            -- Вставить название изначальной таблицы
LATERAL jsonb_each(t.data) AS kv;
```

### Что есть в проекте

- `main.py` - запускаете и при наличии выше созданной таблицы `fin_data` автоматически генерируется таблица с очищенными от влияния активов значениями по счетам. Они хранятся как логарифмы от 10.<br> В файле есть все пояснения.
- `counts.csv` - хранит количество компаний, которые предоставили отчетность по каждому счету в 2020 году. Нужен, чтобы отфильтровать все счета, где количество менее 10 000 шт. Считать что-то по ним все равно смысла нет.
- `codes.csv` - расшифровка номеров счетов в их названия.
- `codes_plus_minus.csv` - Нужен для `gen_fix_table` и `gen_fix_table_split`. В файле указано, какие счета являются строго положительными (p), строго отрицательными (m) и могут принимать оба значения (pm). На основе этого ошибки в знаках в изначальной БД приводятся в норму.
- Папка `analyze` - содержит часть скриптов, использованных при подготовке графиков. Если скрипт `main.py` и связанные с ним я привел в чувства, то здесь царит хаос и беззаконие, будьте осторожны.
